Sélecteur de langue — accessible partout

Problème : aujourd'hui le sélecteur n'existe que sur desktop. Sur mobile, il faut passer par le profil.

Objectif : sur mobile comme desktop, l'utilisateur change la langue de l'interface depuis n'importe quelle page, sans passer par le profil. Au changement → tout le contenu se met à jour dans la nouvelle langue. L'expression du jour reste la même, seule son explication est re-traduite. Comparaison de 3 emplacements pour le déclencheur sur mobile. Le sélecteur lui-même = une bottom sheet (panneau qui remonte) listant les 7 langues.

Pourquoi une bottom sheet ? C'est le pattern mobile natif pour un choix dans une liste : grande zone tactile, 7 langues lisibles d'un coup, fermeture en glissant. Sur desktop on garde le dropdown actuel.
Au tap sur une langue :
localStorage = nouvelle langue→ le contenu se met à jour→ l'expression du jour reste, son explication se re-traduit

Ma recommandation

Option B (header mobile) comme socle, rendue globale pour garantir sa présence sur toutes les pages sans dupliquer le code. C'est l'emplacement le plus attendu (réglages d'app vivent dans le header), il ne chevauche jamais le contenu, et le libellé « FR ▾» est explicite. L'option A est le plan B si l'intégration page-par-page du header s'avère lourde. L'option C est à éviter : la langue n'est pas une destination de navigation.
