### Execution rules

- **Lot API goes first, alone, all the way to `main`** (staging QA → Sinan go →
  merge). Render is a single prod instance deployed from `main`: no front lot
  can be QA'd on staging before the API is live in prod.
- One worktree per lot (`git worktree`), branch off `staging`, PR targets
  `staging`. Merges to `main` are release events (see §3), each behind a
  Sinan go (rule: staging before prod, always).
- Lot owners read `web/AGENTS.md` (Next.js version gotchas) and contract §6
  before writing code. Every visible string goes through a labels file
  (EN + FR filled; fallback English).
- After each lot merge to staging: quick smoke QA (Playwright against staging,
  bypass token in `web/.env.playwright`) before starting a dependent lot.
