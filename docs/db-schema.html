Database schema

World Expressions — PostgreSQL (Neon) · 12 tables · managed with SQLAlchemy + Alembic

Generated 2026-06-12 from models.py + Alembic migrations (the live DB is the source of truth). Indicative volume: ~15,000 expressions, 7 UI languages, 14+ countries.

PK primary key  ·  FK foreign key  ·  UQ unique  ·  composite primary keys are marked on each participating column

1 · Content core

An expression is a cultural artifact: its text is never translated. Everything explanatory lives in two satellite tables — expression_content (native explanation, one row per locale) and content_translations (translation kit for foreign readers: literal, idiomatic equivalent…). Display rule: expression_content takes priority over content_translations for the requested locale.

2 · Taxonomy & cross-language bridges

Two distinct "concept" systems coexist. Tags (canonical English slugs + localized names) are what the UI calls "concepts" — the 540+ thematic pills, grouped into 16 domains via concept_domains. The concepts table is narrower: it links expressions that express the same idea across languages, powering the "Same idea" section with a confidence score.

Relationships at a glance

  • expressions 1 → N expression_content (one row per locale) and 1 → N content_translations (one row per target language)
  • expressions N ↔ N tags via expression_tags · each tag has localized names in tag_names and 1–2 domains in concept_domains
  • expressions N → 1 concepts (nullable, with concept_confidence) — expressions sharing a concept appear in each other's "Same idea" section
  • users 1 → N user_favorites and 1 → N email_tokens
  • Search (4 passes) runs on this schema with PostgreSQL FTS — see docs/search-engine.md
