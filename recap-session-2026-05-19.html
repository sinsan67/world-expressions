9 fonctionnalités construites

Tout le travail de cette session, dans l'ordre chronologique.

UX · Frontend
1 — Renommage du filtre pays : "F from" → "Expressions from"
Le label était ambigu. "Expressions from" clarifie que les drapeaux servent à filtrer la provenance des expressions, pas la langue de l'interface.
Frontend
2 — Menu burger : sélecteur de langue de l'interface
Bouton fixe en haut à droite. Bascule toute l'interface entre EN / FR / ES. Implémenté via un objet T[] de traductions et une fonction applyTranslations(). L'objet T est extensible : ajouter une langue = ajouter un bloc.
Frontend
3 — Icônes sémantiques sur les tags (TAG_ICONS)
Un objet TAG_ICONS de 80+ entrées associe chaque tag à un emoji. La clé du design : les synonymes cross-langues partagent le même pictogramme — argent, money, dinero → 💰. Les tags deviennent visuels et multilingues.
UX · Frontend
4 — Redesign des hint chips en mini-cartes visuelles
Les chips de suggestion passent d'un format pill plat à des mini-cartes avec icône au-dessus du mot. Résultat : plus visuel, plus cliquable, et cohérent avec les icônes sémantiques.
Frontend
5 — Scroll infini : 20 résultats par batch + compteur "X / Y"
Avant : tous les résultats rendus d'un coup. Après : IntersectionObserver sur un sentinel div, PAGE_SIZE = 20, compteur "24 / 89 résultats" visible. Les résultats se chargent au fur et à mesure que l'utilisateur descend.
Backend Frontend
6 — Recherche cross-langue par concept (endpoint /concept)
Problème initial : cliquer sur le tag "argent" ne retournait que des expressions françaises. Solution en deux parties :
— Backend : nouveau endpoint GET /concept?tags=argent,money,dinero,wealth qui fait un OR logique sur les tags
— Frontend : getConceptGroup(tag) inverse TAG_ICONS pour trouver tous les synonymes du tag cliqué, puis appelle /concept avec tous ces synonymes
UX · Frontend
7 — Toggle "Mix countries" : interleaving round-robin par région
Un bouton shuffle discret (⇄ circulaire, 28px) dans la rangée des chips. Par défaut, désactivé — l'ordre API est conservé (exact puis sémantique). Activé : les résultats sont redistribués en round-robin par région (1 🇫🇷, 1 🇺🇸, 1 🇬🇧, 1 🇦🇺, 1 🇪🇸...). Algorithme côté frontend uniquement, pas de nouveau fetch. Inclut une animation fondu au re-render.
UX · Frontend
8 — Tooltip CSS sur le bouton Mix (via attr(title))
Le tooltip natif du navigateur est lent et laid. Solution : ::after avec content: attr(title) — le label (Mix countries / Mezclar países / Mélanger les pays) vient directement de l'attribut HTML, donc il suit automatiquement la langue de l'interface sans JS supplémentaire.
Data Frontend Backend
9 — Ajout de l'espagnol : 120 expressions + chip 🇪🇸 + langue Español
Trois composantes :
— Script Python add_spanish_expressions.py : 120 refranes et expresiones idiomáticas (proverbes, corps humain, animaux, argent, amour...)
— Chip pays 🇪🇸 España dans le filtre "Expressions from", activé par défaut
— Español comme 3ème langue d'interface dans le menu burger, avec traduction complète de tous les textes
— TAG_ICONS enrichis des synonymes espagnols (dinero, miedo, suerte, amor, engaño...)
🧠 Concepts techniques clés

Ce qu'il faut retenir

Les décisions d'architecture qui forment le socle du projet.

🔄

TAG_ICONS — synonymes cross-langues

Le même emoji pour plusieurs langues. getConceptGroup(tag) inverse la map pour retrouver tous les synonymes. C'est ce qui permet la recherche cross-langue au clic d'un tag.

🌍

i18n via T[] + applyTranslations()

Tout le texte de l'interface est dans un objet JS. Ajouter une langue = ajouter un bloc dans T[]. Aucune lib externe, juste des clés et une fonction de mise à jour DOM.

📜

IntersectionObserver pour le scroll infini

Un div sentinel invisible en bas de page. Quand il entre dans le viewport, on charge le prochain batch. Propre, performant, sans polling ni scroll events.

⇄

Round-robin par région (Mix countries)

Grouper par région, créer un tableau de buckets, itérer bucket par bucket. Résultat : résultats équilibrés entre les langues sans toucher le backend.

🗄️

Séparation main.py / database.py

main.py = routes HTTP uniquement. database.py = accès SQLite uniquement. Migrer vers PostgreSQL ne touchera que database.py.

🎨

Tooltip CSS via attr(title)

Le pseudo-élément ::after lit content: attr(title). Pas de JS, pas de lib. Le texte suit la langue de l'interface automatiquement via applyTranslations().

🚀 Prochaines étapes

Ce que je recommande pour la suite

Classées par impact et faisabilité. Les 3 premières peuvent se faire dans la prochaine session.

1
Priorité haute — Session suivante

Déploiement en ligne (Render + Vercel)

Le site tourne en local. Pour que ton cousin puisse le voir et y contribuer, il faut le mettre en ligne. Backend : déployer sur Render.com (gratuit, Python natif). Frontend : déployer sur Vercel ou Netlify (drag-and-drop du fichier HTML). Temps estimé : 1 heure. Impact : le site devient accessible à n'importe qui.

2
Priorité haute — Session suivante

Filtres "Expressions from" dynamiques (issus de l'API)

Actuellement les chips France/UK/USA/AU/España sont codés en dur dans le HTML. Si on ajoute l'italien demain, il faut modifier le HTML manuellement. Solution : l'endpoint GET / retourne déjà by_language — utiliser cette data au chargement pour générer les chips automatiquement. Les drapeaux et labels peuvent être dans un objet JS de config.

3
Priorité haute — Prochaine session

Ajouter l'italien (100–150 expressions)

Tu prépares un voyage en Sicile et tu apprends l'italien — c'est la parfaite motivation. Un script Python similaire à add_spanish_expressions.py suffit. Expressions idiomatiques italiennes : in bocca al lupo, avere le mani in pasta, prendere due piccioni con una fava... Ajouter ensuite le chip 🇮🇹 Italia et la traduction Italiano dans le menu burger.

4
Priorité moyenne — V2

Frontend router : URLs individuelles par expression

Actuellement tout se passe sur une seule page sans URL propre. Pour la navigabilité et le partage, chaque expression devrait avoir une URL : /expression/casser-les-pieds. Implémentable avec un simple hash router (#/expression/id) sans framework. C'est la clé pour que le site soit partageable et indexable.

5
Priorité moyenne — V2

Redesign visuel inspiré d'ethereum.org

Le design actuel est propre mais basique. La référence choisie (ethereum.org) utilise des illustrations SVG, des palettes pastel, des sections alternées, une typographie Playfair Display affirmée. Commence par la page d'accueil : hero avec illustration, section "Explore by theme" avec cards visuelles. Les cartes d'expressions peuvent avoir des emojis illustratifs générés depuis les tags.

6
Priorité moyenne — V2

Page "Parcourir par thème" (tags cliquables → liste)

En cliquant sur un tag, l'utilisateur voit toutes les expressions de ce concept dans toutes les langues. C'est déjà partiellement fonctionnel via /concept, mais il manque une vraie page "tag" avec URL propre, titre, description du concept, et les expressions groupées par langue.

7
Long terme — V3

Carte interactive de France par région

Le champ region est déjà dans la base de données (actuellement : fr/uk/us/au/es). Enrichir les expressions françaises avec leur région d'origine (Normandie, Provence, Alsace...) via le TLFi (CNRS). Une SVG de France cliquable permettrait d'explorer les expressions par terroir. Un projet à envisager en partenariat avec une institution culturelle.

8
Long terme — V3/V4

Illustration SVG par expression (AI → vectorisation)

Chaque expression est unique et mérite une illustration. Le champ illustration est déjà prévu en base. Workflow possible : générer avec Midjourney ou DALL-E → vectoriser → stocker en SVG. Commence par les 10 expressions les plus cherchées pour tester le format visuel.
